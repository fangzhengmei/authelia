## 一、身份提供方属性映射机制

### 1.1 核心数据结构

身份提供方（Identity Provider）负责将后端认证系统（LDAP、文件等）的用户属性映射为 Authelia 内部可用的 Subject 结构。

**Subject 结构体** (`internal/authorization/types.go:48-54`)：
```go
type Subject struct {
    Username string    // 用户名
    Groups   []string  // 用户所属组列表
    ClientID string    // OAuth2 客户端ID
    IP       net.IP    // 客户端IP地址
}
```

**UserDetails 结构体** (`internal/authentication/types.go:19-24`)：
```go
type UserDetails struct {
    Username    string
    DisplayName string
    Emails      []string
    Groups      []string  // 组信息直接从后端映射
}
```

### 1.2 LDAP 属性映射配置

LDAP 后端通过 `AuthenticationBackendLDAPAttributes` 配置属性映射关系 (`internal/configuration/schema/authentication.go:165-192`)：

```go
type AuthenticationBackendLDAPAttributes struct {
    Username          string  // LDAP 属性 → 用户名
    Mail              string  // LDAP 属性 → 邮箱
    MemberOf          string  // LDAP 属性 → 所属组（memberOf）
    GroupName         string  // LDAP 属性 → 组名称
    // ... 其他属性映射
    Extra map[string]AuthenticationBackendLDAPAttributesAttribute  // 自定义额外属性
}
```

不同 LDAP 实现有不同的默认映射：
- **Active Directory**: `sAMAccountName` → Username, `memberOf` → MemberOf, `cn` → GroupName
- **RFC2307bis**: `uid` → Username, `memberOf` → MemberOf, `cn` → GroupName
- **FreeIPA**: `uid` → Username, `memberOf` → MemberOf, `cn` → GroupName

### 1.3 文件后端属性映射

文件后端通过 YAML 文件直接定义用户和组关系 (`internal/configuration/schema/authentication.go:41-47`)：

```go
type AuthenticationBackendFile struct {
    Path            string  // 用户数据库文件路径
    ExtraAttributes map[string]AuthenticationBackendExtraAttribute  // 额外属性配置
}
```

### 1.4 身份信息传递链路

在授权处理器中，身份信息从会话/认证策略提取并构造成 Subject (`internal/handlers/handler_authz.go:192-200`)：

### 2.2 规则编译流程

func NewAccessControlRules(config schema.AccessControl) (rules []*AccessControlRule) {

### 2.3 单条规则编译

`NewAccessControlRule` 将配置规则编译为内部可执行的匹配器 (`internal/authorization/access_control_rule.go:18-37`)：

```go
func NewAccessControlRule(pos int, rule schema.AccessControlRule) *AccessControlRule {
    r := &AccessControlRule{
        Position: pos,
        Query:    NewAccessControlQuery(rule.Query),           // 编译查询参数匹配器
        Methods:  schemaMethodsToACL(rule.Methods),            // 编译HTTP方法匹配器
        Networks: AccessControlNetworks(rule.Networks),        // 编译网络匹配器
        Subjects: schemaSubjectsToACL(rule.Subjects),          // 编译主体匹配器（关键！）
        Policy:   NewLevel(rule.Policy),                       // 编译策略级别
    }
    // 标记是否包含主体规则
    if len(r.Subjects) != 0 {
        r.HasSubjects = true
    }
    ruleAddDomain(rule.Domains, r)                              // 编译域名匹配器
    ruleAddDomainRegex(rule.DomainsRegex, r)                     // 编译正则域名匹配器
    ruleAddResources(rule.Resources, r)                          // 编译资源路径匹配器
    return r
}
```

### 2.4 主体（Subjects）规则编译

`schemaSubjectsToACL` 将配置中的主体规则编译为匹配器链 (`internal/authorization/util.go:123-137`)：

```go
func schemaSubjectsToACL(subjectRules [][]string) (subjects []AccessControlSubjects) {
    for _, subjectRule := range subjectRules {
        subject := AccessControlSubjects{}
        for _, subjectRuleItem := range subjectRule {
            subject.AddSubject(subjectRuleItem)  // 逐个编译主体项
        }
        if len(subject.Subjects) != 0 {
            subjects = append(subjects, subject)
        }
    }
    return subjects
}
```

### 2.5 主体项编译

`schemaSubjectToACLSubject` 根据前缀识别主体类型并创建对应匹配器 (`internal/authorization/util.go:57-77`)：

```go
func schemaSubjectToACLSubject(subjectRule string) (subject SubjectMatcher) {
    if strings.HasPrefix(subjectRule, prefixUser) {  // "user:"
        user := strings.Trim(subjectRule[lenPrefixUser:], " ")
        return AccessControlUser{Name: user}
    }
    if strings.HasPrefix(subjectRule, prefixGroup) {  // "group:"
        group := strings.Trim(subjectRule[lenPrefixGroup:], " ")
        return AccessControlGroup{Name: group}
    }
    if strings.HasPrefix(subjectRule, prefixOAuth2Client) {  // "oauth2:client:"
        clientID := strings.Trim(subjectRule[lenPrefixOAuth2Client:], " ")
        return AccessControlClient{Provider: "OAuth2", ID: clientID}
    }
    return nil
}
```

### 2.6 策略级别编译

`NewLevel` 将字符串策略转换为枚举值 (`internal/authorization/util.go:12-25`)：

```go
func NewLevel(policy string) Level {
    switch policy {
    case bypass:    return Bypass    // 0 - 绕过
    case oneFactor: return OneFactor // 1 - 单因素
    case twoFactor: return TwoFactor // 2 - 双因素
    case deny:      return Denied    // 3 - 拒绝
    }
    return Denied  // 默认拒绝
}
```

## 三、命中规则的优先级和拒绝路径

### 3.1 规则匹配顺序

**按配置顺序匹配，第一个命中即生效** (`internal/authorization/authorizer.go:51-68`)：

```go
func (p *Authorizer) GetRequiredLevel(subject Subject, object Object) (hasSubjects bool, level Level) {
    p.log.Debugf("Check authorization of subject %s and object %s (method %s).",
        subject.String(), object.String(), object.Method)

    for _, rule := range p.rules {  // 按配置顺序遍历
        if rule.IsMatch(subject, object) {
            p.log.Tracef(traceFmtACLHitMiss, "HIT", rule.Position, subject, object, object.Method, rule.Policy)
            return rule.HasSubjects, rule.Policy  // 第一个命中即返回
        }
        p.log.Tracef(traceFmtACLHitMiss, "MISS", rule.Position, subject, object, object.Method, rule.Policy)
    }

    p.log.Debugf("No matching rule for subject %s and url %s (method %s) applying default policy", subject, object, object.Method)
    return false, p.defaultPolicy  // 无命中则用默认策略
}
```

**关键点**：
- 规则按配置顺序（`Position` 字段）遍历
- **第一个匹配成功的规则立即生效**，后续规则不再检查
- 无匹配规则时应用 `defaultPolicy`（默认为 `deny`）

### 3.2 单条规则匹配逻辑

`IsMatch` 按顺序检查所有匹配条件，**全部满足才命中** (`internal/authorization/access_control_rule.go:54-80`)：

```go
func (acr *AccessControlRule) IsMatch(subject Subject, object Object) (match bool) {
    if !acr.MatchesDomains(subject, object) { return false }    // 1. 域名匹配
    if !acr.MatchesResources(subject, object) { return false }  // 2. 资源匹配
    if !acr.MatchesQuery(object) { return false }               // 3. 查询参数匹配
    if !acr.MatchesMethods(object) { return false }             // 4. HTTP方法匹配
    if !acr.MatchesNetworks(subject) { return false }           // 5. 网络匹配
    if !acr.MatchesSubjects(subject) { return false }           // 6. 主体匹配
    return true
}
```

### 3.3 主体匹配逻辑

`MatchesSubjects` 处理匿名用户和已认证用户的不同匹配逻辑 (`internal/authorization/access_control_rule.go:149-155`)：

```go
func (acr *AccessControlRule) MatchesSubjects(subject Subject) (match bool) {
    if subject.IsAnonymous() {
        return true  // 匿名用户自动通过主体检查（规则不包含主体约束时）
    }
    return acr.MatchesSubjectExact(subject)
}
```

`MatchesSubjectExact` 进行精确主体匹配 (`internal/authorization/access_control_rule.go:158-174`)：

```go
func (acr *AccessControlRule) MatchesSubjectExact(subject Subject) (match bool) {
    if len(acr.Subjects) == 0 {
        return true  // 规则无主体约束 → 匹配
    } else if subject.IsAnonymous() {
        return false // 规则有主体约束但用户匿名 → 不匹配
    }
    // 遍历主体规则，OR 关系（任意一个匹配即可）
    for _, subjectRule := range acr.Subjects {
        if subjectRule.IsMatch(subject) {
            return true
        }
    }
    return false
}
```

### 3.4 组匹配实现

`AccessControlGroup.IsMatch` 检查组名是否在用户组列表中 (`internal/authorization/access_control_subjects.go:48-50`)：

```go
func (acg AccessControlGroup) IsMatch(subject Subject) (match bool) {
    return utils.IsStringInSlice(acg.Name, subject.Groups)
}
```

### 3.5 主体规则组内匹配

`AccessControlSubjects.IsMatch` 实现 AND 逻辑（组内所有条件必须同时满足） (`internal/authorization/access_control_subjects.go:22-30`)：

```go
func (acs AccessControlSubjects) IsMatch(subject Subject) (match bool) {
    for _, rule := range acs.Subjects {
        if !rule.IsMatch(subject) {
            return false  // 有一个不满足则整个组不匹配
        }
    }
    return true  // 全部满足则组匹配
}
```

**配置示例与匹配逻辑**：
```yaml
subject:
  - ["group:admins", "user:john"]    # AND 关系：必须是admins组且用户是john
  - ["group:developers"]             # OR 关系：或者是developers组
```

### 3.6 动态域名中的主体/组匹配

域名支持 `{user}` 和 `{group}` 占位符 (`internal/authorization/access_control_domain.go:63-84`)：

```go
func (m AccessControlDomainMatcher) IsMatch(domain string, subject Subject) (match bool) {
    switch {
    case m.UserWildcard:  // {user}.example.com
        return domain == fmt.Sprintf("%s%s", subject.Username, m.Name)
    case m.GroupWildcard: // {group}.example.com
        i := strings.Index(domain, ".")
        return domain[i:] == m.Name && utils.IsStringInSliceFold(domain[:i], subject.Groups)
    }
}
```

### 3.7 拒绝路径（授权结果判定）

`isAuthzResult` 函数决定最终授权结果 (`internal/handlers/handler_authz_util.go:28-43`)：

```go
func isAuthzResult(level authentication.Level, required authorization.Level, ruleHasSubject bool) AuthzResult {
    switch {
    case required == authorization.Bypass:
        return AuthzResultAuthorized  // Bypass → 直接授权
    case required == authorization.Denied && (level != authentication.NotAuthenticated || !ruleHasSubject):
        // 拒绝策略且用户已认证，或规则无主体约束 → 直接禁止
        return AuthzResultForbidden
    case required == authorization.OneFactor && level >= authentication.OneFactor,
         required == authorization.TwoFactor && level >= authentication.TwoFactor:
        return AuthzResultAuthorized  // 认证级别足够 → 授权
    default:
        return AuthzResultUnauthorized  // 需要更多认证 → 未授权（重定向登录）
    }
}
```

**拒绝路径流程图**：
```
规则命中 → 策略为 Denied
    ↓
用户已认证? 或 规则无主体约束?
    ├─ 是 → 返回 Forbidden (403)
    └─ 否 → 返回 Unauthorized (需要登录)

规则命中 → 策略为 OneFactor/TwoFactor
    ↓
认证级别足够?
    ├─ 是 → 返回 Authorized (200)
    └─ 否 → 返回 Unauthorized (需要更多认证)
```

### 3.8 授权结果处理

`handler_authz.go:221-237` 根据结果执行不同动作：

```go
switch isAuthzResult(authn.Level, required, ruleHasSubject) {
case AuthzResultForbidden:
    ctx.GetLogger().Infof("Access to '%s' is forbidden to user '%s'", object.URL.String(), authn.Username)
    ctx.ReplyForbidden()  // 403 Forbidden

case AuthzResultAuthorized:
    authz.handleAuthorized(ctx, authn)  // 200 OK，设置头信息
}
```

## 四、热重载时旧策略的清除机制

### 4.1 文件监视器初始化

`ProvisionUsersFileWatcher` 初始化文件监视器 (`internal/service/file_watcher.go:15-32`)：

```go
func ProvisionUsersFileWatcher(ctx Context) (service Provider, err error) {
    config := ctx.GetConfiguration()
    providers := ctx.GetProviders()

    if config.AuthenticationBackend.File != nil && config.AuthenticationBackend.File.Watch {
        provider, ok := providers.UserProvider.(*authentication.FileUserProvider)
        if !ok { return nil, errors.New("error occurred asserting user provider") }
        service, err = NewFileWatcher("users", config.AuthenticationBackend.File.Path, provider, ctx.GetLogger())
    }
    return service, nil
}
```

### 4.2 文件监视器运行

`FileWatcher.Run` 监听文件系统事件 (`internal/service/file_watcher.go:114-166`)：

```go
func (service *FileWatcher) Run() (err error) {
    // ...
    for {
        select {
        case event, ok := <-service.watcher.Events:
            // 过滤无关文件
            if service.file != "" && service.file != filepath.Base(event.Name) {
                break
            }
            // 处理写入/创建事件
            switch {
            case event.Op&fsnotify.Write == fsnotify.Write, event.Op&fsnotify.Create == fsnotify.Create:
                log.Debug("File modification was detected")
                var reloaded bool
                switch reloaded, err = service.reload.Reload(); {  // 触发重载
                case err != nil:
                    // 错误处理
                case reloaded:
                    log.Info("Reloaded successfully")
                }
            }
        }
    }
}
```

### 4.3 FileUserProvider 重载实现

`FileUserProvider.Reload` 实现线程安全的用户数据库重载 (`internal/authentication/file_user_provider.go:55-78`)：

```go
func (p *FileUserProvider) Reload() (reloaded bool, err error) {
    now := time.Now()

    p.mutex.Lock()         // 写锁，阻塞所有读操作
    defer p.mutex.Unlock()

    // 冷却时间检查（防止频繁重载）
    if now.Before(p.timeoutReload) {
        return false, &errReload{err: ErrWatcherCooldown}
    }

    switch err = p.database.Load(); {  // 加载新数据
    case err == nil:
        p.setTimeoutReload(now)
    case errors.Is(err, ErrWatcherNoContent):
        return false, &errReload{err: err}
    default:
        return false, &errReload{err: fmt.Errorf("failed to reload: %w", err), critical: true}
    }

    p.setTimeoutReload(now)
    return true, nil
}
```

### 4.4 旧数据清除机制

`FileUserDatabase.Load` 实现旧数据的完全替换 (`internal/authentication/file_user_provider_database.go:71-87`)：

```go
func (m *FileUserDatabase) Load() (err error) {
    yml := &FileDatabaseModel{Users: map[string]FileDatabaseUserDetailsModel{}}

    if err = yml.Read(m.Path); err != nil {  // 读取新文件
        return fmt.Errorf("error reading the authentication database: %w", err)
    }

    m.Lock()  // 数据库级别的锁
    defer m.Unlock()

    if err = yml.ReadToFileUserDatabase(m, m.Extra); err != nil {  // 解析新数据
        return fmt.Errorf("error decoding the authentication database: %w", err)
    }

    return m.LoadAliases()  // 重建别名索引
}
```

`ReadToFileUserDatabase` 通过**整体替换 map** 实现旧数据清除 (`internal/authentication/file_user_provider_database.go:349-369`)：

```go
func (m *FileDatabaseModel) ReadToFileUserDatabase(db *FileUserDatabase, extra map[string]expression.ExtraAttribute) (err error) {
    users := map[string]FileUserDatabaseUserDetails{}  // 新建空map

    var udm *FileUserDatabaseUserDetails

    for username, details := range m.Users {
        if err = details.ValidateExtra(username, extra); err != nil {
            return err
        }
        if udm, err = details.ToDatabaseUserDetailsModel(username); err != nil {
            return err
        }
        users[username] = *udm  // 填充新数据
    }

    db.Users = users  // 整体替换，旧map被GC回收 → 旧数据清除！
    return nil
}
```

### 4.5 并发安全保证

**双重锁机制**：
1. `FileUserProvider.mutex` - 保护 Reload 操作的互斥锁
2. `FileUserDatabase.mutex` - 保护数据库读写的互斥锁

**关键要点**：
- 使用 `sync.Mutex` 确保同一时间只有一个 goroutine 执行重载
- 新数据在锁外完全构建（读取、解析、验证），减少锁持有时间
- 通过整体赋值 `db.Users = users` 实现原子替换
- 旧的 `map` 不再被引用，由 Go GC 自动回收

### 4.6 冷却时间机制

防止文件系统事件触发频繁重载：

```go
if now.Before(p.timeoutReload) {
    return false, &errReload{err: ErrWatcherCooldown}
}
// 重载成功后设置下一次可重载时间
p.setTimeoutReload(now)
```

### 4.7 错误处理策略

- **`ErrWatcherCooldown`**：冷却时间内，跳过重载（非严重错误）
- **`ErrWatcherNoContent`**：文件为空，跳过重载（非严重错误）
- **其他错误**：标记为 `critical: true`，记录错误日志

## 五、完整调用链路总结

### 5.1 策略评估完整流程

```
HTTP 请求
    ↓
handler_authz.go: Handler()
    ├─ 构造 Object (URL, Method, Domain)
    ├─ 认证策略获取用户信息 (authn)
    ├─ 构造 Subject (Username, Groups, ClientID, IP)
    ↓
authorizer.go: GetRequiredLevel(subject, object)
    ├─ 按顺序遍历 rules
    │   ↓
    │   access_control_rule.go: IsMatch(subject, object)
    │   ├─ MatchesDomains()  → 支持 {user}/{group} 动态匹配
    │   ├─ MatchesResources()
    │   ├─ MatchesQuery()
    │   ├─ MatchesMethods()
    │   ├─ MatchesNetworks()
    │   └─ MatchesSubjects()
    │       ├─ 匿名用户 → 自动通过
    │       └─ 已认证用户 → 遍历 Subjects 规则
    │           ├─ AccessControlUser.IsMatch()  → username 精确匹配
    │           └─ AccessControlGroup.IsMatch() → Groups 包含匹配
    ├─ 第一个命中的规则 → 返回策略
    └─ 无命中 → 返回 defaultPolicy
    ↓
handler_authz_util.go: isAuthzResult()
    ├─ Bypass → Authorized (200)
    ├─ Denied → Forbidden (403) 或 Unauthorized
    ├─ OneFactor/TwoFactor → 检查认证级别
    └─ 级别不足 → Unauthorized (重定向)
```

### 5.2 热重载完整流程

```
文件系统事件 (Write/Create)
    ↓
file_watcher.go: Run() 检测到事件
    ├─ 过滤无关文件
    └─ 调用 reload.Reload()
        ↓
file_user_provider.go: Reload()
    ├─ mutex.Lock()  [线程安全]
    ├─ 冷却时间检查
    ├─ database.Load()
    │   ↓
    │   file_user_provider_database.go: Load()
    │   ├─ 读取新文件
    │   ├─ Lock()  [数据库锁]
    │   ├─ ReadToFileUserDatabase()
    │   │   ├─ 新建空 map
    │   │   ├─ 解析填充新数据
    │   │   └─ db.Users = users  [整体替换，旧数据被GC]
    │   └─ LoadAliases()  [重建索引]
    ├─ 设置冷却时间
    └─ mutex.Unlock()
```

## 六、关键设计要点

1. **顺序匹配**：规则按配置顺序匹配，第一个命中即生效，管理员可通过配置顺序控制优先级
2. **全条件匹配**：单条规则内所有条件（域名、资源、方法、网络、主体）必须同时满足
3. **主体OR逻辑**：多个主体规则组之间是 OR 关系，组内是 AND 关系
4. **动态匹配**：域名支持 `{user}` 和 `{group}` 占位符，实现基于身份的动态访问控制
5. **原子替换**：热重载时通过整体替换 map 实现旧数据清除，保证并发安全
6. **双重锁机制**：Reload 操作和数据库操作各有锁，防止并发问题
7. **默认拒绝**：无匹配规则时应用默认策略，默认配置为 `deny`，确保安全
8. **拒绝区分**：`Denied` 策略区分已认证用户（403）和匿名用户（重定向登录）
